# Editor Stage 3: Tile Editing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Edit the tile layers of a cell `.tmx` in the viewer (palette, paint, erase, fills, eyedropper, undo/redo) and save a file WorldEd still opens, changing only what the user edited.

**Architecture:** `worlded-core` gets a lossless `TmxDoc` (the original text plus the byte spans of each layer's `<data>`; saving splices re-encoded data into the original text, so everything else is untouched) and a UI-free `edit` module (`Edit`, `History`, tools as pure functions). `worlded-app` adds the palette, tool bar, cursor and save/close handling on top of the existing cell view.

**Tech Stack:** Rust 2021, existing crates (`roxmltree`, `flate2`, `base64`, `eframe`); WorldEd command line (`PZWorldEd_cli.exe` from KnoxMap's `vendor/PZMappingTools/bin`) only to make fixtures and for the acceptance test.

**Spec:** `docs/superpowers/specs/2026-11-15-editing-design.md`

## Global Constraints

- Opening and saving without edits must change nothing except what XML normalisation allows; edits touch only the `<data>` of changed layers (spec: "Edits touch only layer data").
- The saved `<data>` uses the same encoding and compression the file used.
- Edits store changed squares only; never copy a whole layer per edit.
- A TMX the writer cannot save safely opens read-only with a banner (spec: error handling).
- Save is atomic (temp file then rename) and keeps a `.bak` of the previous file on the first save of a session.
- Damaged input is an `Err`, never a panic (as in the other crates).
- Viewer behaviour from stage 1 stays: read-only mode still works for files the editor cannot save.
- MIT, clean-room: the TMX layout comes from real files and observed WorldEd behaviour.

## Review Focus

- A drag across the map edge or over a locked or hidden layer: nothing changes outside the map, status bar says why, no panic.
- Bucket fill on an empty 300x300 layer: bounded and fast, one undo step restores it.
- Undo after save, then save again: file matches the undone state; dirty marker correct.
- A tile name that is in no tileset of the file: added as a new tileset entry, file still loads.
- Save failure (read-only file, disk full): old file untouched, document stays dirty, message shown.

## File Structure

- `rust/worlded-core/src/tmxdoc.rs`: `TmxDoc` (text + spans + decoded layers), `save_to_string`.
- `rust/worlded-core/src/edit.rs`: `Edit`, `History`, tools.
- `rust/worlded-core/src/gids.rs`: tile name to gid, adding tilesets.
- `rust/worlded-core/src/save.rs`: atomic save with `.bak`.
- `rust/worlded-core/tests/data/`: two real fixtures (Task 1), small synthetic ones.
- `rust/worlded-app/src/{palette,tools,document}.rs` and changes to `cell_view.rs`, `main.rs`.
- `FORMATS.md` (TMX section completed in Task 1).
